# Phase 7 Owner and Currentness Audit — ResearchArena Contract Evidence

## Purpose and authority

This artifact preserves the Phase 7 owner/currentness audit evidence for the ResearchArena contract: whether existing product owners can express EvidencePacket resolution, arena/session identity, dissent carry, parked-alternative return, and the manifest/LLM/human projections without a new persisted research authority. It is evidence input to the roadmap kickoff gate, not a second status, architecture, or verification authority. All repository claims carry file:line references against the audited working tree (2026-08-28, HEAD `33ee506a`); all live claims come from read-only HTTP calls against the approved local `pnpm backend:dev:prisma` process. The audit was independently cross-reviewed by Codex (gpt-5.6-sol, read-only); its seven confirmed corrections — G1 section-text reconstructibility, stage-specific disposition bans, minority-report survival vs classification, the typed v1a stop reason, LLM-path narrative-risk re-entry, the AcceptedRisk human-authority boundary, and service-path (not purely DB-structural) no-fork enforcement — are incorporated in this version.

## 3. Arena/session identity owner map

The repository holds four stage-local debate runtimes — v1a need-discovery (explorer/deep-critic/issue-frame/final-synthesis, its own loop), and v1b N6 / v1b N8 / v1c N2 sharing `TopicSelectionBoundedDebateCoreService` — with strong per-turn validation: role-slot manifests, instance policies, named execution plans (`codex_assisted`/`provider_compact`/`provider_diverse`, the latter identity/provenance-only), prompt-packet identity, runtime-invocation context with `debate_context`, and deterministic admission that re-derives every role identity, pins schemas, scans forbidden authority keys, and re-folds transcript hashes. Debates are deliberately `support_only`, enforced stage-specifically: only v1c N2 lists literal `disposition` among forbidden authority keys (v1c-n2-bounded-debate-admission-service.ts:190-204); N6/N8 runtime schemas allow additional properties and omit it from their forbidden lists — their support-only boundary is instead enforced by stage-specific authority-key scans plus the bridge, which lets only the synthesizer's draft reach the single-agent gate path.

Element-by-element verdict (A = expressible as a new nested `payload_schema` on `TopicSelectionArtifactRef` + convention; B = needs a real table/column for queryability or integrity):

## 4. Dissent and risk-carry owner map

**The seam that lets a green gate coexist with material N8 risk is N8/N9/N10, not v1c.** Everything from N11 onward faithfully carries refs — it faithfully carries an empty set. Two independent breaks:

1. **Material risk is written as prose, never minted as a ref.** N8's `risk_notes`/`reviewer_objections` (TopicValueAssessment), the memo's `reviewerRisks`/`topObjections`/`criticTriggers`, and N10's `TitleCardPackage.keyRisks` are `string[]`; the N10 merge flattens six upstream sources into one provenance-destroying array (topic-selection-v1b-topic-package-service.ts:831-840). `TopicSelectionAcceptedRisk` rows are minted only by the explicit human `acceptRisk` route and override path (coverage acceptance and recheck resolution merely attach caller-supplied refs) — **no N8/N9/N10 code path mints one**. The N9 warning `N9_VALUE_RISK_NOTES_CARRIED_FORWARD` fires on non-empty risk notes but attaches `decision.accepted_risk_refs`, which is empty when no risk was formally accepted: a "risk carried forward" warning with zero refs.
2. **The deterministic v1c support path computes warnings exclusively from ref arrays, so narrative risk cannot re-enter it.** `compileSupportWarnings` (v1c-promotion-gate-service.ts:972-997) and the mini-check emit warnings only when `accepted_risk_refs`/`blocker_refs` are non-empty; the deterministic dossier hardcodes `critic_finding_resolution_map: []` (:1659), so on this path `N8_CRITIC_REVIEW_TRIGGERED` can never become `UNRESOLVED_INDEPENDENT_CRITIC_FINDING`, and empty warnings mean `pass_with_risk_findings` is empty so `UNMAPPED_PASS_WITH_RISK_FINDING` never fires. Scope caveat: the LLM/bounded-debate v1c path **can** re-inject narrative risk — `createLlmDraft` sends the complete handoff including package and assessment snapshots (:624-641), `buildDossierPayload` uses the draft's `n3_semantic_layer` instead of the empty default (:1622-1659), and the human-decision service converts that critic map into checkpoint findings (v1c-human-promotion-decision-service.ts:459-497) — but that re-entry is model-discretionary, not guaranteed. The live frozen gate ran the deterministic path (`llm_draft_payload=null`) and its zero-warning state is fully explained field-by-field by these two breaks; the risk text still exists in `riskPenalty.penalty_summary`, `keyRisks`, and the N8/N9/N10 `ReadinessGateResult.warnings` — nothing on the deterministic path reads any of them.

Consequences for the contract:

- **This is a missing write, not a missing projection.** A projection cannot recover what was never recorded as a ref. Three of four disposition kinds already have complete owners with stable identity and terminal states (objection + unique resolution; `AcceptedRisk.status ∈ {active, expired, resolved, revoked, superseded}`; recheck impact/resolution; decision `loopbackTarget/loopbackRefs`).
- **Minimal repair — a neutral risk-finding owner, not machine-minted AcceptedRisk.** `acceptRisk` is a human authority by contract: it requires a human/hybrid actor and an expiry or recheck condition (recheck-risk-memory-service.ts:428-460, 953-955), so N8/N9 must not mint `TopicSelectionAcceptedRisk` rows. Instead, mint a machine-owned **risk finding** (new small owner or typed extension) per material N8 `risk_note`/capped dimension/`critic_trigger`, carry finding refs through the existing N9→N10→N11→v1c ref arrays (a small ref-array widening, no semantic change to v1c), and let the promotion checkpoint's existing mapping semantics require each finding to end in an explicit human accepted-risk, owned action, or disposition — exactly the `UNMAPPED_PASS_WITH_RISK_FINDING` tripwire, now fed with real findings. Optionally widen `keyRisks` entries from `string` to `{summary, source_ref, finding_ref}`.
- **Secondary gaps:** objections with severity `info`/`warning` are invisible to every gate (`BLOCKING_OBJECTION_SEVERITIES = {blocking, critical}`), so "material" needs a definition independent of that set; and the recheck subsystem cannot carry an arena-level ref today — no `research_objection` event type exists, `stageForRef` would misclassify `need_candidate_arena` refs via its `includes('need')` branch, and nothing outside the checkpoint service reads `TopicSelectionResearchObjection`.

## 5. Parked-alternative return and supersession thought experiment

**No-fork safety holds for the audited production service path — four cooperating layers make a second ACTIVE lineage impossible through it.** The DB layers alone do not carry the whole guarantee: the CHECK constraint only ties status to nullability/supersession pointers, and nothing at DB level enforces the `${titleCardId}:${checkpointKind}` key format — that convention is supplied solely by the service's `currentKey` builder (checkpoint-service.ts:1662-1664). Every checkpoint write flows through this one service path today, and the layers are:

1. DB unique index `tsrc_current_key_key` on `currentCheckpointKey = ${titleCardId}:${checkpointKind}` (migration 20260825120000:151) — at most one non-NULL current row per title-card+stage; superseded history is unbounded because NULLs are distinct.
2. DB CHECK `tsrc_current_state_chk` makes current and superseded mutually exclusive: a superseded row can never be resurrected into a second head, and a current row can never carry a supersession pointer.
3. `replaceCurrentCheckpoint` demotes-then-creates under a Serializable transaction with content-addressed replay (`checkpointKey = sha256(packetIdentity)`): identical packets replay to one row; different packets serialize into a linear supersession chain; races resolve to replay or 409.
4. Every decision/advance is a compare-and-swap `updateMany` on `{id, currentCheckpointKey, status:'pending'}` requiring `count===1` — a decision attaches only to the row current at commit time.

**Thought experiment — parked candidates cannot collide with the active lineage, because candidates are not lineage.** A NeedCandidate never holds a `currentCheckpointKey`; the arena is one synthetic `need_candidate_arena` target ref hashed over the whole candidate set, and exactly one current `gap_selection` checkpoint exists per title card. Marking a candidate parked changes candidate facts → changes the arena's `targetSnapshotHash` → triggers ordinary supersession of the single head, never a sibling. Delta-gated serial return is the same mechanism in reverse: the recorded delta produces a new arena version that supersedes the old one, and downstream checkpoints go stale through the existing predecessor-ref validation. One contact point to preserve: if a parked candidate is also excluded from `machine_viable`, parking the only alternative correctly flips the arena to `COMPETING_CANDIDATE_REQUIRED`/`loopback_required` rather than forking.

**Parking itself, however, is a missing write today.** `decision_status='parked'` exists but is reachable only through a separate full adjudication cycle; the gap-review `viable_alternative` disposition has **zero write-back** — non-selected candidates stay `hypothesis`/`machine_checked` and the review lives only inside the checkpoint packet JSON. No column exists for parking reason, reopening conditions, or the binding to the selected candidate. Minimal candidates (per the improvement-register precedents `AcceptedRisk.recheckCondition/expiresAt`, `DecisionMemoryEntry.recheckCondition`, `mergedIntoNeedCandidateId`): `parkReason`/`parkReasonCode`, `reopenCondition`/`reopenExpiresAt`, `parkedAgainstNeedCandidateId` + `distinctnessAxes`. A weaker no-column variant (write back non-selected status in `confirmValidatedNeed` plus a `parked_candidate` DecisionMemoryEntry) yields status and a recheck condition but no reason code or delta binding.

## 6. Projection reuse map (manifest / human stage files / LLM working plane)

All three target views are achievable as **pure read-time projections with zero new writable authority** — every datum in the hand-authored `phase6-a9-owner-map.md` is already reachable through existing `find*`/`list*` repository methods.

Existing foundations:

- `getResearchStatus` (topic-selection-research-checkpoint-service.ts:1333-1387) is fully deterministic and read-only; checkpoint packets are computed at read time from the immutable `TopicSelectionInputSnapshot.payload` and re-hashed against the stored `packet_hash` (409 on drift) — **no packet-content table exists** (confirmed by model sweep).
- `inspectPrePromotionChain` (service:1401-1459) already emits per-stage `{checkpoint_ref, target_ref, provenance_class, advancing, issue_codes}` rows — a ready-made manifest row shape, currently private and 3-stage; generalizing it is the manifest core.
- Per-stage current owners are reachable via existing title-card list routes across v1a/v1b/v1c; promotion support/dossier are persisted JSON owners with pure `findById` reads.
- The legacy-write rejection already names `/topic-selection/title-cards/{id}/research-status` as the single `canonical_recovery` pointer — the de-facto current-pointer contract today.

Reuse map:

| View | Suppliers at read time | New code (projection only) |
|---|---|---|
| Manifest / current-pointer | `getResearchStatus` + generalized `inspectPrePromotionChain` + existing per-stage list repos | One `StageManifestService` fanning out existing list calls; the one real design cost is an explicit per-stage "current" selection rule for stages without a current column (checkpoints have `currentCheckpointKey` unique, N9 has `isCurrent`, promotion has `currentPromotionInputSnapshotKey`; others need documented latest-wins) |
| Human stage files | Stage packet payloads (evidence/gap/question/promotion), `getNeedValidationEvidenceBundle`, value assessment + memo + disposition, package + boundary check + readiness, promotion support + dossier + gate | Pure `record → Markdown` renderers plus a dispatcher. Two constraints: no `text/markdown` precedent exists anywhere in the API (18k-line OpenAPI has zero non-JSON content types) — return Markdown as a JSON string field to stay inside existing contract-drift tooling; and `getNeedValidationEvidenceBundle` stamps `generated_at: now()`, which must be omitted or caller-supplied for deterministic regeneration |
| LLM working plane | Same owners unabridged, addressed via the manifest; token budgeting/compression (`TokenBudgetGateService`, `CompressionRuntimeService`) and the context-packet compile/resolve/cache pattern reuse as-is | Thin manifest→slice resolution + JSON passthrough. **Write-risk caveat:** the context-packet cache's `recordFreshArtifact`/`recordRuntimeCacheArtifact` write `ArtifactRef` rows — the working-plane read surface must call `lookup`/`resolve` only |

Route placement: the unversioned `topic-selection-research-checkpoint-routes.ts` namespace (`/topic-selection/title-cards/:id/*`) is the natural home for a `stage-views` family; controller pattern mirrors `TopicSelectionResearchCheckpointController`. One adjacent gap: `PromotionDossier.reviewerPacketArtifactRef` has **no read route in the v1c namespace** (only v1b exposes `GET .../workflow-harness/artifacts/:artifactRefId`); a manifest surfacing artifact ids should be paired with a generic read-only artifact route over the existing `ControlPlaneService.getArtifactRef`.

This validates the 2026-08-28 decision to prefer manifest-first read-time projection: no persisted working-plane corpus is needed, and the human/LLM views cannot become a second content authority because they have no write path at all.

## 9. Verdict on the open owner decision

Roadmap question: *"Can current owners express EvidencePacket resolution, arena/session identity, and manifest/LLM/human projections without a new persisted ResearchArena authority?"*

**Answer: yes for everything except the arena session itself.**

1. **EvidencePacket — no new authority.** A read-time projection over existing owners, plus two bounded additions on existing paths: a locator→text resolution read service (gaps G1/G6; paragraph/anchor/abstract resolve from durable DB text today, proven live) and typed role/query-intent plus hit-granular provenance on the retrieval path (G3/G4). Excerpt authority remains the literature fulltext owners. Quote integrity (G2) and unit-level freshness (G5) are validation additions, not new owners.
2. **Manifest / human stage files / LLM working plane — no new authority, no persistence at all.** Pure read-time projections over existing `find*`/`list*` methods; the only design cost is a documented per-stage current-selection rule. Confirms the projection-first decision.
3. **Dissent carry — a missing write, repaired with a neutral machine-owned risk-finding record (small owner or typed extension), not machine-minted AcceptedRisk.** `AcceptedRisk` stays a human authority (human/hybrid actor + expiry/recheck condition required); findings ride the existing ref pipeline after a small ref-array widening, and promotion's existing mapping semantics force each finding into an explicit human disposition. Objection severity semantics and recheck ref-type coverage need widening, not new tables.
4. **Parked alternatives — no new authority; small columns (or a write-back + memory-entry variant) on `TopicSelectionNeedCandidate`.** The four-layer one-current enforcement makes parked/active collision structurally impossible; delta-gated serial return maps onto ordinary supersession. The no-fork decision is safe.
5. **Arena session — one minimal new persisted coordination owner IS required at the session root.** Existing owners cannot supply session identity (no node-attempt column anywhere; turn-grouping is a full scan over JSON payloads with a documented concurrency hole), pre-exposure independence proof (structurally violated by the shared divergent loop), minority-report linkage/classification (raw outputs survive but nothing marks or queries them), loop-delta admission (no cross-attempt seam), or arena supersession. These are integrity properties; payload conventions can claim but not prove them. The per-role-execution layer is required as *schema*, but its shape — a new child table versus typed indexed columns on `TopicSelectionArtifactRef` — is a Phase 8 design detail, since per-turn outputs already persist as artifact rows.

**Recommended minimal shape (design candidate for kickoff confirmation):**

- `TopicSelectionResearchArenaSession` — root row modeled on `TopicSelectionResearchCheckpoint`: arena kind (semantic stage), target ref, bound `input_snapshot_id` + snapshot hash, policy/plan identity, status (`open/synthesized/superseded`), `current_arena_key @unique` for one-current-per-stage, supersession pointers, enumerated `termination_reason`, `loop_transcript_hash`, and **delta refs to the superseded session** (the persisted loop-delta admission seam).
- Role-execution integrity layer — role slot id, instance index, **exposure-set hash** (admission rejects a first-pass output whose exposure set contains peer artifacts), evidence-partition refs, output artifact ref/hash, prior-role hashes, unique runtime identity hash. Shape open for Phase 8: a child table modeled on `PaperImplementationRuntimeArtifact`, or typed indexed columns on `TopicSelectionArtifactRef` (which already durably holds every turn's output) — the integrity fields and admission blocker are required either way.
- Minority reports and arena candidate genealogy ride existing patterns (objection-shaped rows or `FunctionalLineageLink` edges) referenced from the session root; the arena's disposition stays advisory (`support_only` preserved) and becomes binding only through the existing gap checkpoint + HumanConfirmNeed, which records the arena session ref in its `source_refs`.

This is a **coordination owner, not a content authority**: research content (candidates, evidence, questions, decisions) stays in existing owners; the new rows own only session identity, role-execution integrity, termination, delta, and supersession — exactly the boundary `02-architecture.md` reserved for a Phase 7-proven necessity. Checkpoint-kind overloading was considered and rejected: checkpoints are human-decision-scoped (`decisionAuthorityRef`, `humanConfirmedDecisionId`) while arenas are advisory, and mixing them would blur the authority boundary the control plane exists to keep.
