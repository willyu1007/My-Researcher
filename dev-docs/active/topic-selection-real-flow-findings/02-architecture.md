## Settled design and boundaries

- The research checkpoint packet remains the canonical decision input and strict-human authority boundary.
- N6 Debate is a regular topic-question convergence component, not only a failure-recovery mechanism. The existing Explorer/Critic/Arbiter divergent loop and single deterministic N6 gate remain the implementation primitives; the product-fix route must select a bounded default and retain deeper escalation without creating a second authority gate.
- Human and LLM stage views remain deterministic read projections; they do not persist a second interpretation or decision authority.
- Evidence source statements, roles, freshness, attribution, locators, material conflicts, falsifiers, and claim ceiling must remain traceable to the packet and its referenced EvidenceMap.
- Literature coverage and freshness limitations that can reverse a novelty judgment must be visible in the human decision packet; absence from the managed pool is not evidence of novelty.
- The EvidenceMap runtime validator remains the behavior authority while Phase 1 determines the intended public request surface; contract alignment must not silently expand accepted behavior.
- Topic-selection verification uses supported APIs and replaceable fixtures, never direct database access.
- Backup/restore readiness and per-query experiment signals are adjacent findings until an owning boundary is confirmed.
- EvidenceMap admission currently treats optional functional-ref scoping fields as identity-bearing; Phase 1 must determine whether callers must preserve the exact SearchRun ref shape or the boundary should canonicalize equivalent refs.
- Literature acquisition and embedding remain operational dependencies: effective downloader limits need preflight validation, and embedding persistence must not require a second paid provider call after a transaction timeout. The reproduced persistence seam currently performs one pgvector `UPDATE` per chunk inside Prisma's default 5-second interactive transaction; 205 chunks exceeded that bound while smaller papers completed.
- A checkpoint decision and a TitleCard management status are currently separate authorities: an evidence-landscape `reject` closes the checkpoint but does not change the TitleCard's `active` status. The intended workbench projection or state transition must be settled before implementation.

## Migration and operation

Presentation and OpenAPI changes should be backward compatible with existing checkpoint and EvidenceMap records. Provider-backed verification requires explicit authorization, a cost disclosure, and read-before-replay recovery; irreplaceable experiment runs and user-owned checkpoint decisions remain out of bounds. Existing immutable decision lineage is retained; reruns use fresh replaceable rehearsal records.

For the remainder of this authorized local rehearsal, safe starts and restarts of the same loopback development backend are covered by the research-flow authorization and do not require repeated prompts. This standing authorization does not cover a different environment, external provider or cost, destructive/control effects, or a new strict-human decision.
