# Topic-Selection Workflow Matrix (SSOT)

## Purpose & Ownership
- 本文件是 topic-selection 全链（resource-sampling → v1a → v1b → v1c → downstream）节点分类的**唯一语义入口（SSOT）**。任何 ordinary agent / multi-agent debate / Codex-assisted / provider-backed / deterministic / human-review 决策都必须绑定到具体 `node_id`。
- 叙述性章节可以解释理由，但**不得定义矩阵中不存在的行为**。
- 历史：由 T-089（agent-workflow-review）创建于 `dev-docs/active/topic-selection-agent-workflow-review/06-workflow-matrix.md`；T-123 Phase 0（2026-06-11）完成实现对齐并迁移至本永久位置。新增 debate 节点分类的语义裁决仍归 T-089 职责域。
- 节点策略细节（blockers/validators 全文）见各 contracts 文件与 T-089 `07-node-policies.md`（历史详情）。

## Machine-Check Contract
本文件由一致性脚本自动校验：`.ai/scripts/topic-selection-workflow-matrix-consistency.mjs`（接入 backend 默认测试套件）。

| v1b node_id 集合 | Matrix 表 stage=v1b 行 | `TOPIC_SELECTION_V1B_WORKFLOW_HARNESS_NODE_IDS`（…/topic-selection-v1b-workflow-harness-contracts.ts） |

| 契约抽取完备性 | —— | 每个 v1b node 必须抽取到 policy modes+execution_kind（防常量化重构令校验静默失效）；每个 v1c/downstream node 必须有 policy 条目；未映射的 v1b `execution_kind` 显式报错 |

解析格式约定（修改表格结构前必须同步脚本）：
- 矩阵行所在表的表头第一列必须是 `node_id`，单元格用反引号包裹完整 node_id。
- Slot Map 表头第一列是 `node_id`、第二列是 `slot_id`，v1b 行的 slot_id 用反引号包裹。
- 语义列取**行首 token**（`/^[a-z_]+/`）比对，括号内注解不参与校验；被校验的布尔列以 `yes`/`no` 前缀解析（出现 `conditional`/`reserved` 会 fail-closed 报 unparseable，属有意设计——扩展词汇前先扩展契约导出与脚本）。
- `covered_scenarios` 单元格内 scenario id 必须用反引号包裹（脚本按反引号提取）。
- **仍未自动校验（按列精确表述）**：v1a 与 resource_sampling 行的**全部**语义列（无结构化契约导出源，T-089 backlog ①尾巴）；v1b 行的 `provider_required` / `debate_allowed` / `debate_primitive` / `human_review_required` 四列（v1b 契约无对应布尔导出——v1b 已校验的是 codex_allowed / executor_kind / human_delegated_allowed / default_execution_mode 四列）；v1c/downstream 行全部 8 列**已**校验。

## Required Fields
- `node_id` / `stage` / `authority_object` / `executor_kind` / `default_execution_mode`
- `codex_allowed` / `provider_required`
- `debate_allowed`：`no | yes | conditional | reserved`
- `debate_primitive`：`divergent_loop`（发散循环：explorer/deep_critic/arbiter，多实例多轮，用于生成型节点）| `bounded_sequence`（有界对抗序列：固定角色顺序单遍，用于评估型节点）| `reserved`（debate 钩子已预埋或被政策允许，但无可执行 scenario 定义——触发必须 blocked，见 DMP-03）| `none`
- `human_review_required`：产品要求人审决定才能推进（硬人审门）
- `human_delegated_allowed`：契约允许 `human_delegated` 执行模式（人可介入，但非必须）
- `input_refs` / `output_refs` / `blocking_conditions` / `deterministic_validators` / `audit_refs` / `artifact_refs` / `covered_scenarios`

### Slot-map rules
- Single-agent slots use `execution_spec` and never use instance-level overrides.
- Debate worker slots may use `execution_plan.instances` only when their scenario `instance_policy` permits multiple instances.
- Debate arbiter / bounded-sequence final slots may use slot-level overrides only; instance overrides are forbidden.
- `model_option_id` is legal only for `provider_llm`.
- `none` is legal only for explicitly designed deterministic/caller-supplied-draft paths such as v1a N5 `evidence_extraction` and v1b N7 mechanical materialization; it is not a model-like execution mode.

### Debate Decisions（含拒绝理由）
- **v1a need adjudication（rejected）**: adjudication consumes a selected `NeedCandidate` plus sibling candidate-pool context, applies structured routing, and relies on human confirmation (v1a N8) for final validation authority.
- **v1c promotion gate（rejected）**: the gate must remain deterministic over support, dossier, snapshot, blockers, and accepted-risk refs.
- **v1c downstream feedback/recheck（rejected）**: first-pass routing should remain typed and deterministic; later debate requires a matrix update.
- **v1b N4 generate-research-slice-options（rejected, 2026-06-11）**: 人在 N5 做真实选择，人即 critic；对抗辩论的价值由选择环节承担。允许 multi-instance 发散采样（diversity_policy 形态，复用 explorer instance_policy 语义）以扩大选项覆盖面，但不构成 debate。
- **v1b N6 generate-topic-question-candidates（implemented divergent_loop — 2026-06-20，T-127 W-07）**: 由 reserved 实装为完整运行时（登记 D-T127-02）。原语 = `divergent_loop`（explorer→critic→arbiter fan-out，复用共享 debate-core 的 `runDivergentLoop`，与 N8/v1c bounded_sequence byte-identical 共存）。链路:`n6_loopback_triage` 工件判定升级（advisory `n6_debate_trigger_thresholds`，provisional 待 W-13 标定）→ harness 检测/路由 `debate_escalation` loopback（debate **执行在 caller 端**,镜像 N8 `runDebate` / v1c N2,harness 不内调）→ caller 跑 `runDivergentDebate`(fan-out → 确定性 admission〔role-order/arity/forbidden-keys/per-instance drift/`[slot,arity]` transcript 重折〕→ arbiter `synthesized_candidate_set` 拆裸 5-key draft → gate bridge 复用既有单 agent draft 路径铸 single-agent 身份)→ re-enter harness 经**既有** `N6TopicQuestionCandidateGate`（零新 gate,DMP-10）。harness 侧另发 product 下的 `N6_DEBATE_THRESHOLDS_PROVISIONAL` advisory tripwire（gated escalation+product,replay byte-identity 保持）。scenario `v1b_n6_divergent_candidate_debate`;实现见 `topic-selection-backend-hardening-and-expansion` Phase 3 W-07 f0–f6;协调 T-089（本矩阵即 SSOT 留痕）。
- **v1b N8 assess-topic-value（conditional bounded_sequence — implemented 2026-06-13）**: 价值评估存在天然张力（值不值得做/reviewer 风险/负面记忆），单 agent 易自洽偏乐观。计划复用 v1c N2 的有界对抗序列运行时，信号触发（borderline/rerun 漂移/维度冲突/operator 强制），scenario `topic-selection.debate.v1b-value-tension.v1` 当前仅政策。实现归 T-123 Phase 3：触发器量化 = N8 node policy `debate_trigger_thresholds`（provisional, DP-3.3 待标定），DMP-13 已锁定原语二分 + N6 同形触发/准入语义。

### Human Surface Decisions
- **v1b N2 / N5（human surfaces, T-115 done）**: `human_delegated` 经 harness 单写入口；产品默认人驱动（N2 研究者撰写约束档案、N5 真人选切片），codex 路径并存（验收/批跑）。
- **v1b N7（contract-capable but product-mechanical, T-115 verified）**: 契约允许 `human_delegated`，但 `runN7MaterializeTopicQuestionContract` 用 `chooseN7Candidate` 算法机械物化，Initial frozen-input 无人审决策内容 → 产品不开人审面，UI 保持只读。本行登记契约能力，产品决策以本注记为准。
- **v1a N8 / v1c N4（hard human gates）**: 产品要求人审决定才能推进；v1a N8 附带 bounded semantic review（codex 可在人授权边界内执行）；v1c N4 另有 delegated candidate runtime（候选产物，最终决定权在人）。

### Provider Required Reasons
- No node is provider-required. Provider execution is scenario-driven or explicit override until a future node policy updates this matrix.（唯一例外语义：v1a `arbiter.final_synthesis` 在 real run 中必须 provider_llm，见 slot map。）

### Codex Allowed Reasons
- Codex is allowed for single-agent and support slots to preserve the personal local-first cost model while keeping shared schema validation, guardrails, and provenance.
- Codex is not allowed for deterministic or human-review nodes because those nodes do not invoke model-like execution.
