## Phase 6 - Candidate Staging Schema
- Status: repo SSOT completed and local dev DB applied.
- Objective: add a dedicated DB staging surface for broad discovery candidates before B10 scaleout.
- Candidate entities:
  - `LiteratureDiscoveryBatch`
  - `LiteratureDiscoveryCandidate`
- Excluded entity:
  - no separate `CandidateDecisionLog` table in the initial implementation.
- Required properties:
  - batch run summary fields: `batchCode`, `directionScope`, `sourceProviders`, `queryLedger`, `summaryStats`, `status`, `errorSummary`, `completedAt`.
  - candidate metadata fields: `title`, `normalizedTitle`, `abstractText`, `authors`, `year`, `venue`.
  - source identity fields: `doiNormalized`, `arxivId`, `openalexId`, `semanticScholarId`, `dblpUrl`, `sourceUrl`.
  - source provenance fields: `sourceProvider`, `sourcePayload`.
  - dedup fields: `dedupKey`, `duplicateReason`, `duplicateConfidence`.
  - lightweight scoring fields: `directionScores`, `roleScores`, `relevanceScore`, `implementationScore`, `theoryScore`.
  - current decision fields: `status`, `decisionReason`, `decisionAt`.
  - link fields: `matchedCandidateId`, `matchedLiteratureId`, `promotedLiteratureId`.
- Lifecycle statuses:
  - `DISCOVERED`
  - `DUPLICATE`
  - `REJECTED`
  - `DEFERRED`
  - `READY_FOR_PROMOTION`
  - `PROMOTED`
- Boundary:
  - candidate staging is not evidence-ready literature.
  - candidate staging rows do not count as managed corpus or effective literature.
  - candidate staging rows are promoted only through B11.
  - obvious duplicates may be marked at candidate stage, but they are not deleted.
  - B11 duplicate decisions are reverse-marked on candidate records.
  - decision history is not retained beyond the current candidate row state.
  - operational errors are recorded in batch summaries or `decisionReason`, not as extra lifecycle statuses.
  - first-version indexes are ordinary lookup indexes, not authoritative unique constraints.
  - first-version Prisma draft uses `String` status fields instead of Prisma enums to match existing status-field conventions.
  - after B11 promotion, the existing `LiteratureRecord` and standard pipeline flow remains unchanged.
