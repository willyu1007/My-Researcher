## Confirmed design baseline and implementation deltas

- ART-B confirmed baseline: v1 artifact refs mean exact EF-controlled Run declaration plus canonical envelope/source-hash sealing. They do not mean independent artifact-byte verification; the P5 conclusion stays on typed observations and P1 adds no extra artifact fetch/storage subsystem.
- CMP-B1 confirmed baseline: restrict M0-SCI v1 to protocol-registered, two-cell, same-unit directional absolute differences with non-overlapping support/contradiction bands, an indeterminate gap and an optional conservative CI guard. EF emits one factual ordered/hash-bound relation/reason separately from eligibility and never emits a PI disposition.
- PI proposal census: the existing immutable ResultAnalysis runtime artifact id/hash can serve as proposal identity, so no proposal table is needed. Its current multi-scenario payload needs a new admitted one-proposal version for scientific closure.
- DISP-S confirmed baseline: one protocol-designated primary relation maps deterministically to disposition and the admission-frozen exit. The caller only invokes or withholds the exact Closure command; limitations and claim ceiling carry contextual caution, while corrected-disposition/review-choice inputs are prohibited.
- PI closure census: the current closure table already has the required disposition, selected-exit, accepted-proposal, watermark and hash fields. The scientific branch is a service/contract gap, not a storage-model gap.
- PKT-S confirmed baseline: the existing Packet table lacks exact Closure/content-hash binding. Add the four-field reference-centered binding plus one replay-idempotent closure-event materializer; proposal/disposition/exit remain Closure-owned, with no second Packet store or distributed transaction.
- P5-ELIG-S confirmed baseline: add a deterministic eligibility validator, exact hash-bound execution package and generated acceptance record while reusing default-off process-scoped capability windows. Do not add an outcome target, manual eligibility override, hidden Job substitution or standing enablement.
- P0 decisions D-136-64 through D-136-68 are confirmed. No Prisma, application code, local database, capability state or cloud resource was changed while freezing them.
