# BYOC 产品化升级方向

## 结论

论文工程助手后期产品化 MAY 继续采用可下载、local-first 的桌面产品形态，并以 BYOC（Bring Your Own Cloud，用户自带云资源）作为远程对象存储的优先方向。

在该方向下，用户自行创建和付费使用阿里云 OSS、Amazon S3 或后续支持的兼容对象存储。产品不必提供托管云账号、统一云资源池或代付云账单。

本文只记录当前讨论方向，不是完整产品方案、实施计划或已经批准的交付承诺。

## 产品与用户的责任边界

产品 SHOULD 负责：

- 提供对象存储配置向导，解释 Endpoint、Region、Bucket、访问方式和可选前缀。
- 提供连通性、读写权限、加密和生命周期配置检查。
- 提供最小权限策略模板和明确的错误诊断，不要求用户使用主账号或长期高权限凭据。
- 通过操作系统安全存储保存本地凭据；凭据 MUST NOT 写入项目仓库、日志或可导出的项目文档。
- 将供应商差异封装在对象存储适配层后，向业务层提供稳定、供应商中立的存储契约。
- 在产生上传、删除或云计算费用前展示影响，并保留用户确认边界。

用户 SHOULD 负责：

- 注册和维护自己的云账号，接受供应商协议并承担云费用。
- 创建 Bucket、选择地域、配置账单告警，并决定数据驻留和合规边界。
- 按产品提供的最小权限模板创建或授权身份。
- 决定数据保留期、备份和最终删除策略。

## 首选安全边界

- Bucket 默认 MUST 为私有，并 SHOULD 开启阻止公共访问和服务端加密。
- 产品 MUST NOT 要求云账号主密钥；优先使用短时凭据、受限角色或用户创建的专用低权限身份。
- 产品 SHOULD 在保存配置前执行只读探测，在首次实际写入前执行显式写入验证。
- 不同项目的数据 SHOULD 使用独立前缀；是否要求每项目独立 Bucket 留待后续产品决策。
- 对象键、日志和错误信息 MUST 避免泄露凭据或包含不必要的论文敏感内容。

## 对产品架构的影响

BYOC 会降低产品对多租户云基础设施、统一云计费和托管资源编排的依赖，但不会消除以下产品能力：

- 供应商中立的对象存储接口与能力探测。
- 本地安全凭据管理和凭据轮换。
- 上传队列、断点恢复、幂等、重试、限流和成本提示。
- 数据授权、保留、导出和删除记录。
- 可诊断但不泄密的运行日志。
- 配置迁移和供应商切换支持。

账号登录、多设备同步、团队协作和商业许可 MAY 独立演进；它们不应与“产品必须托管用户云资源”绑定。

## 与 T-132 的关系

T-132 M7-L1 创建的 OSS、RAM 和 ACR 资源用于验证真实供应商执行边界。它们是开发与诊断资源，不代表未来产品必须提供统一的阿里云托管方案。

T-132 中形成的最小权限、不可变镜像、对象清单、成本上限和显式外部副作用确认机制，SHOULD 复用于未来 BYOC 配置向导和供应商适配层。

## 后续待讨论事项

- 首发只支持阿里云 OSS，还是同时定义 S3-compatible 契约。
- 凭据模式采用短时 STS、专用 AccessKey、实例角色或多种方式并存。
- 一个 Bucket 多项目隔离与每项目独立 Bucket 的默认选择。
- 对象存储仅承载实验输入/输出，还是也参与多设备同步与备份。
- 产品对生命周期规则、跨地域、版本控制和灾备承担何种检查责任。
- BYOC 故障的支持边界，以及产品如何生成不含凭据的诊断包。
