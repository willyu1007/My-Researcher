## runtime / harness / workflow-agents 分工配合审查结论
- **边界方向实测干净**：harness service 仅依赖 3 个 repo + 契约，不 import orchestrator/gateway/provider，不算 prompt/cache/token identity（`paper-implementation-ai-workflow-harness-service.ts:32-41`）；11 个 runtime service 构造依赖仅 runtimeAdmission + agentOrchestrator(+retrieval)，无域仓库句柄（结构性写不了权威）、无 harness 引用；无任何 paper-implementation service 直连 llm-gateway。workflow agents（LLM 角色）全部经共享 orchestrator 单点执行。
- **no-dual-track 成立**：proposal artifact（harness lane）与 runtime envelope 类型/表分离；runtime slot 的 forbidden primary inputs 拒绝 harness 产物冒充（各 runtime service 强制）；Domain Gate 只收 admitted final envelope。
- **配合面的真实问题不是越界而是"零接线"**：队列归 harness lane 独有，runtime lane 的 blocked/failed 不入队（N5）；provider variance 为 evaluation-only fake lane；`mocked_llm`/`codex_assisted` 的语义输出由请求方注入（runtime service 前置拒绝是单层防线，product 模式靠 request 校验兜底）。
- **验证面机制**：L5 runtime-stress 为 `node --test` 编排（进程内测试面 + 套件锁，`.ai/scripts/paper-implementation-runtime-stress.mjs`），near-prod gate 走真实路由——harness"验证生产路径但不成为第二生产者"的声明与代码一致。
- 结论：分工声明与代码高度一致（T-114 边界成果保持）；产品化风险集中在两 lane 之间缺失的协作接点（队列物化、失败善后、受理桥），归 S1 承接。

## 新发现清单（N1..N9，均已实锤）

### N1 [P0] 强 claim 人工确认可被 LLM 伪造（治理洞）

- 归属：S0。

### N2 [P0] admission 自证恒等 + per-role 语义校验零实现（语义空心可 passed）
- 服务内自 admit 时 expected_* 全部拷贝自 artifact 自身（`paper-implementation-trace-integrity-debate-runtime-service.ts:767-800`），admission 的 8 项 hash 比对在该路径恒真（`paper-implementation-runtime-admission-service.ts:186-214`）；实际生效仅 scope 匹配、failed_runtime 拒收、blocked 无码拒收、envelope schema 四道。admission 亦不从 payload 重算 hash。外部 admit 端点具独立复核价值但无产品调用方。
- 11 号设计文档承诺的 per-role/final admission 规则（`cited_source_refs ⊆ retrieval packet`、每 skeptic finding 恰一处置、rebuttal 必须引 ref、arbiter 全覆盖）零实现——refs-within-packet 校验全仓 0 命中。role output 契约过平（summary 字符串 + blocker_codes + 两组 refs，`paper-implementation-runtime-contracts.ts` role output 定义），per-statement support map / per-finding disposition 在 schema 上不可表示：模型漏答一半 statement 仍可 passed。
- 所有 slot 的服务端语义检查仅在 `role_status='passed'` 时执行——provider 返回 blocked+编造码即可绕过全部结构约束并拿到 admitted blocked final（结合 N4 的"admitted 含 blocked"可继续冒充下游输入）。
- 归属：S3（契约加深 + admission 真实现）；blocked 旁路修复归 S2。

### N3 [P0] debate 链条经济性：无断点续跑 + token 双计 + 压缩未接线 + 不幂等
- 任一角色 admission 拒绝或 failed_runtime → 整场 `failed_runtime`、final=null、重跑从 role 1 全价（`trace-integrity-debate-runtime-service.ts:210-220`）；P1 3 角色同构（`paper-implementation-p1-runtime-review-service.ts:307-330`）。整链成功率≈p^n（p=0.95 时 4 角色≈81%）。
- token 估算双重计入：role messages 整包嵌入 retrieval packet+prior outputs（`:856-871`），context_payloads 再放一份同内容（`:883-897`），估算=两份之和/4（`:898-903`）——24k 目标实际可用≈12k，第 4 角色最先爆。
- orchestrator 压缩恢复通道已存在（T-128 W-11 caller-supplied），paper 侧无一 slot 供 `compression_attempt`（全服务 grep 0 命中）→ over-budget 死点落在最贵的角色上。
- 不幂等：runtime_artifact_id 永远新 UUID，Prisma runtimeIdentityHash 仅 index 无 unique、project 无 FK；无并发锁；admission dedup 含新 UUID 不去重。缓存身份 per-run（retrieval_packet_id 含 runId），跨 run 必 miss，缓存体系是纯审计制品。
- 两类合法输出绕过重试直接打死链：模型回显错误 role_slot_id（schema enum 允许全部值）→ recordRoleArtifact 抛 HTTP 400、前角色成孤儿（`:411-417`）；`role_status='blocked'`+空 blocker_codes → admission 拒收 → 整链 failed_runtime。
- 归属：断点续跑=S3（D9 resume 契约）；双计/压缩/重试分类/幂等=S2。
