# T-107 Deep Acceptance Matrix

Status: accepted supplement to the T-107 exit gate. This matrix explains what the v1b WorkflowHarness acceptance proves, what each node is expected to do, and where output-quality evidence is backed by deterministic fixtures, constrained live-provider canaries, or still-bounded residual risk.

If this matrix conflicts with executable contracts or `08-exit-gate-review.md`, the executable contracts and exit gate decision win.

## Scope

T-107 acceptance is service-level WorkflowHarness acceptance from frozen v1a handoff to v1c input publication. It proves harness admission, deterministic gates, replay/idempotency, typed routing, authority boundaries, and frozen semantic-artifact quality gates.

T-107 now includes constrained live-provider and Codex-assisted script paths over current local content, a full v1b harness-native HTTP N1-N11 chain for local automation, a standalone v1b harness e2e runner, current N4/N6/N8 provider slot canaries, historical DashScope/OpenAI repeat=3 provider evidence, a two-sample current-content v1a Codex-assisted to v1b OpenAI provider batch, external bundled-Codex CLI N4/N6/N8 variance probes, historical provider-backed negative loopback/readmission evidence, and a Prisma-backed harness HTTP smoke. The active v1b runtime path now covers negative/loopback semantics through deterministic runtime stress, while provider-required-live evidence is slot-level. It still does not prove full multi-turn human-interactive Codex sessions, long-running scheduled operational stability, or broader production readiness beyond the recorded canaries.
